## About

I'm a **QA Automation Engineer / SDET** who treats quality as an engineering discipline—not a gate at the end of the pipeline.

I design **automation frameworks**, **test strategies**, and **developer-facing tooling** that improve release confidence and reduce manual toil. I work closely with engineers, product owners, and stakeholders to keep coverage meaningful and feedback loops short.

When I'm not in the test suite, I'm usually shipping **CLI utilities in Go and TypeScript** to automate repetitive workflows and tighten development cycles.

## What I work on

| Area | Focus |
|------|--------|
| **Test automation** | End-to-end, API, and data-layer validation across web and mobile |
| **Framework design** | Maintainable suites, clear conventions, and CI-friendly execution |
| **Developer experience** | Tools and workflows that help teams ship with less friction |
| **AI in QA** | MCP integrations per stack, plus assistants for triage and exploration—always grounded in solid test design |

## Currently learning

- **Svelte & SvelteKit** — compiler-first UI, routing, and lean full-stack patterns
- **AI for QA** — practical adoption: MCP hooks into existing stacks, faster triage, and repeatable workflows without replacing engineering judgment
